# ETL – Loading

## Types of Load

There are mainly **2 types of loading**:

1. **Initial Load**
2. **Incremental Load**

---

## 1. Initial Load

Initial load is the **first full load** of data into the Data Warehouse.

It is usually done **once before the Data Warehouse goes live**.

```text
Source → Extract → Transform → Full Load → Data Warehouse
```

### Example

If the source has 10 million records, the initial load loads the required 10 million records into the DW.

**Remember:**
`Initial Load = First + Full Load`

---

# 2. Incremental Load

After the initial load, we don't want to load all data again and again.

Instead, we load only the **new or changed data**.

```text
Initial Load
     ↓
Data Warehouse
     ↓
New / Changed Data
     ↓
Incremental Load
```

### Why?

To keep the Data Warehouse **up to date** while avoiding unnecessary full loads.

### Example

```text
Day 1 → 1000 records loaded
Day 2 → 50 new/changed records
```

On Day 2, we process only those **50 records**, not all 1050 records.

---

## What Data Can Come in Incremental Load?

### 1. New Data

Example:

* New customer
* New product
* New transaction

### 2. Modified Data

Example:

* Employee gets promoted → role changes
* Product price changes

### 3. Deleted Data

Sometimes data is deleted according to business rules.

However, instead of physically deleting a record, we often mark it as:

```text
status = Inactive
```

---

# Types of Incremental Load

## 1. Append

New records are simply **added at the end**.

```text
Existing Data + New Data
```

Example:

```text
Before → A B C

New → D E

After → A B C D E
```

**Used when:** Existing records do not need to be updated.

---

## 2. In-Place Update

An existing record is directly updated with the new value.

```text
Before:
Customer A → Price = 100

After:
Customer A → Price = 120
```

The old value is **overwritten**.

> In-place update is commonly associated with **SCD Type 1**.

---

## 3. Complete Replacement

The existing dataset is completely replaced by the new dataset.

```text
Old Data → Remove
New Data → Load completely
```

This is **not commonly used** for normal incremental processing because it can be expensive.

---

## 4. Rolling Append

New data is appended, but old data is removed to maintain a fixed retention period.

### Example

Requirement:

```text
Run → Monthly
Keep → Last 24 months
```

Initially:

```text
24 months of data
```

After adding the new month's data:

```text
25 months
```

Remove the oldest month:

```text
24 months
```

This is called **Rolling Append**.

```text
Append New Data
      ↓
Remove Oldest Data
      ↓
Maintain Fixed Period
```

---

# Quick Comparison

| Load Type            | What happens?                     |
| -------------------- | --------------------------------- |
| Initial Load         | Load all data for the first time  |
| Append               | Add new records                   |
| In-Place Update      | Update existing records           |
| Complete Replacement | Replace the entire dataset        |
| Rolling Append       | Add new data + remove oldest data |

# Interview Questions

### Q1. What is Initial Load?

Initial load is the **first full load of source data into the Data Warehouse**, usually performed before going live.

### Q2. What is Incremental Load?

Incremental load loads only the **new or changed data** instead of loading the complete dataset again.

### Q3. Why do we use Incremental Load?

To:

* Reduce processing time
* Reduce resource usage
* Avoid unnecessary full loads
* Keep the Data Warehouse up to date

### Q4. What are common types of Incremental Load?

* Append
* In-place update
* Complete replacement
* Rolling append

---

## Remember

```text
Initial Load     → Full data
Incremental Load → New / Changed data

Append           → Add
In-Place Update  → Overwrite
Replacement      → Replace everything
Rolling Append   → Add new + remove old
```

**Most important interview topic:**
Be ready to explain **how you identify and load only the new/changed records** during an incremental load.
