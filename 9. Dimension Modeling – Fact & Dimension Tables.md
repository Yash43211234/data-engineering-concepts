# Dimension Modeling – Fact & Dimension Tables

## 1. What is Dimension Modeling?

**Dimension Modeling** is a way of designing Data Warehouse tables so that business data can be easily **stored, queried, and analyzed**.

The two main types of tables are:

* **Fact Table** → Stores measurements
* **Dimension Table** → Stores context/details

---

# 2. Fact Table

A **Fact Table stores measurable business values**, usually numbers.

Example in retail:

```text
Sales Quantity
Unit Price
Sales Amount
Discount
Cost
```

Example:

| Transaction ID | Product ID | Quantity | Sales Amount | Discount |
| -------------- | ---------- | -------: | -----------: | -------: |
| 101            | 5          |        2 |          200 |       10 |

Here, `Quantity`, `Sales Amount`, and `Discount` are **measurements**.

### Remember

> **Fact = What happened / How much?**

---

# 3. Dimension Table

A **Dimension Table provides context/details about the facts.**

Example:

### Product Dimension

| Product ID | Product Name    | Brand    | Category | Weight |
| ---------- | --------------- | -------- | -------- | ------ |
| 5          | Roasted Peanuts | Haldiram | Snacks   | 500g   |

It tells us **what the product actually is**.

Other common dimensions:

* **Date Dimension** → date, month, quarter, year, weekday
* **Store Dimension** → store, city, state, country
* **Product Dimension** → product, brand, category
* **Promotion Dimension** → promotion name, code, media type, start/end date

### Remember

> **Dimension = Context / Details**

---

# 4. Fact + Dimension Relationship

The Fact Table contains **foreign keys** that connect it to Dimension Tables.

Example:

```text
                 Date Dimension
                      ↑
                      |
Store Dimension ← Fact Table → Product Dimension
                      |
                      ↓
              Promotion Dimension
```

Example:

```text
Fact Table
Product ID = 5
        ↓
Product Dimension
Product ID = 5
        ↓
Product Name = Roasted Peanuts
Brand = Haldiram
Category = Snacks
```

So the Fact Table tells us:

> "5 units were sold."

The Dimension tells us:

> "Those 5 units were Haldiram Roasted Peanuts."

# 6. Why Multiple Dimensions?

Because a business fact can need context from different areas.

For a sales transaction, we may want to know:

* **What** was sold? → Product
* **When** was it sold? → Date
* **Where** was it sold? → Store
* **Under which promotion?** → Promotion

This allows us to answer questions such as:

> Which products sold the most on weekends in a particular store during a promotion?

---

# 7. Key Idea

```text
                 DIM_DATE
                    |
DIM_STORE →     FACT_SALES     ← DIM_PRODUCT
                    |
               DIM_PROMOTION
```

**Fact Table = Measurements**

**Dimension Tables = Context**

# Interview Questions

### Q1. What is a Fact Table?

A Fact Table stores **measurable business data**, such as sales amount, quantity, cost, and discount.

### Q2. What is a Dimension Table?

A Dimension Table stores **descriptive information that provides context to the facts**, such as product, store, date, and promotion details.

### Q3. How are Fact and Dimension tables connected?

Usually through **keys**. The Fact Table contains foreign keys that reference the corresponding Dimension Tables.

### Q4. Give an example.

For a retail sale:

```text
Fact → Quantity = 5, Sales = ₹500
Dimension → Product = Haldiram Peanuts
Dimension → Store = Kolkata Store
Dimension → Date = 10-Sep-2026
```

---

## Remember

```text
FACT      → Measurement
DIMENSION → Context

FACT      → How much?
DIMENSION → What / Where / When / Which?
```

**Most important:**
When you see a Data Warehouse model, identify **Fact = measurements** and **Dimensions = context/details** first.
