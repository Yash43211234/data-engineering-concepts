# Data Warehouse Internals

## 1. Data Warehouse Layers

A Data Warehouse mainly has two important layers:

1. **Staging Layer**
2. **User Access Layer**

```text
Source Systems
     ↓
    ETL
     ↓
Staging Layer
     ↓
Transformation / Modeling
     ↓
User Access Layer
     ↓
BI / Business Users
```

### User Access Layer

* The layer used by **BI tools and business users**.
* Contains data in a business-friendly structure.
* Business users generally **do not get access to Staging Layer**.

---

# 2. What is Staging Layer?

**Staging Layer = Landing area where data is first stored inside the Data Warehouse.**

Its main purpose is to **quickly extract and land data from source systems**.

### Important

At the staging layer:

* Data is usually kept close to the source format.
* No major transformation/modeling is performed.
* Data is first landed here.
* Later it moves to the User Access Layer.

> **Staging = Land the data first, transform it later.**

---

# 3. Why Do We Need Staging Layer?

The main reason is to **separate extraction from transformation**.

For example:

```text
Source
  ↓
Extract quickly
  ↓
Staging
  ↓
Transform / Model
  ↓
User Access Layer
```

This allows the extraction process to focus on **getting data as quickly as possible**, without worrying about dimensional modeling at the same time.

---

# 4. Types of Staging Layer

There are two common types:

### 1. Non-Persistent Staging

Data is kept only temporarily.

```text
Source → Staging → User Access Layer
                  ↓
             Staging emptied
```

Once processing is completed, the staging data is removed/truncated.

### Advantages

* Less storage required.
* Less long-term sensitive data stored.

### Disadvantages

* If the Data Warehouse has a problem, data must be extracted again from the source.
* Difficult to perform historical debugging/QA from staging.

---

### 2. Persistent Staging

Data remains in the staging layer even after processing.

```text
Source → Staging → User Access Layer
           ↑
       Data remains
```

New data is added to the existing staging data.

### Advantages

* Useful for **debugging and data quality checks**.
* Can rebuild the User Access Layer without going back to the source.
* Historical source data is available for investigation.

### Disadvantages

* Requires more storage.
* More security and governance is required because sensitive data remains stored.

---

# 5. Persistent vs Non-Persistent

| Persistent               | Non-Persistent                         |
| ------------------------ | -------------------------------------- |
| Data remains             | Data is removed after processing       |
| More storage             | Less storage                           |
| Better for debugging/QA  | Less useful for historical debugging   |
| Can rebuild from staging | May need source again                  |
| More security required   | Lower storage-related security concern |

---

# 6. Important Flow

Suppose a new store's data arrives:

```text
Source System
     ↓
Extract
     ↓
Staging Layer
     ↓
Combine / Transform / Model
     ↓
User Access Layer
```

**Staging Layer:** Get the data in quickly.

**User Access Layer:** Make the data ready for users/BI.

---

# 7. Interview Questions

### What is a Staging Layer?

> A staging layer is a temporary or persistent landing area where data is first loaded from source systems before it is transformed and loaded into the user-access layer.

### Why do we need a Staging Layer?

> It separates data extraction from transformation and provides a landing area where source data can be processed before being made available to users.

### Types of Staging Layer?

> Persistent and Non-Persistent staging.

### Persistent vs Non-Persistent?

> Persistent staging keeps the extracted data for future debugging, recovery, or reprocessing, while non-persistent staging removes the data after processing is completed.
